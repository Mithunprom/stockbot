## WHAT SHIPPED THIS WEEK (W39)

### v0.7.0 — ROOT CAUSE FOUND AND FIXED (MERGED Sep 21 05:45 UTC)

The desk diagnosed and fixed the train/serve skew that explains M2's entire performance failure. This is the most significant deploy since v0.6.0.

**Root cause (measured, not guessed):**
- 11 of 30 model features diverged between the training and live serving paths
- Primary: `obv` — cumulative sum anchored to the start of whatever series was passed in; training used full sessions, live used a 300-bar rolling window; the two paths started counting at different points and could NEVER agree regardless of window size
- Secondary: `mtf_*` features — Wilder EWM needs multiple sessions to converge; 300 bars = 0.77 sessions, insufficient
- Result: live predictions ranked entries at ~**46th percentile** of the model's own cross-section instead of the top decile

| Percentile band | n | Mean return | WR | PF |
|---|---|---|---|---|
| Top decile (target) | 90 | +1.667% | 86.7% | 10.55 |
| ~46th pctile (actual) | 90 | -0.291% | 33.3% | 0.34 |
| Production M2 | 111 | -0.491% | 33.3% | 0.27 |

Win rate matches to the decimal. **The bot was not trading a bad strategy. It was trading the right strategy on corrupted inputs.**

**Changes in v0.7.0:**
1. **Feature pipeline v2** — OBV session-anchored; `WARMUP_BARS` 300→1950 (5 sessions for MTF convergence); rank agreement 0.36→0.87; long bias eliminated
2. **Feature version guard** — model refuses to load if trained on different feature version (fail-closed; prevents silent skew recurrence)
3. **Feature archive** — durable S3/local archive; backfilled 99 sessions (2026-04-22→09-11); retrain path no longer limited to 3-day table
4. **Retrained model (pipeline v2)** — OOS IC15=0.1795, dir_acc=0.5605, per-ticker IC positive on 100% of 75 tickers
5. **Sector/correlation guards fail-closed** — SECTOR_MAP 24→57 tickers; unknown ticker→1 slot (not shared "other" bucket); harness evidence: fail-closed blocks 13 concentration episodes vs 3 previously; counterfactual PF 0.86→1.16
6. **Exit barriers actually binding (H14)** — hold-window-scaled ATR stops (sqrt(30/390)=0.277 factor); floors 1%/0.8%/1.5%→0.25%/0.35%/0.35%; 2.0σ stop, 3.0σ TP/trail; 0/111 M2 trades had working barriers; now they bind
7. **Kelly entry block actually works** — `kelly_entries_blocked` was hardcoded `False`; now computed; `KELLY_HARD_BLOCK_THRESHOLD=-0.25` blocks ALL entries when edge is strongly negative; exits unaffected (cannot strand positions); self-draining within 10 days
8. **Entry rank monitor** — `entry_rank_pctile` logged per fill; `entry_rank_mean/n/healthy` at `/diagnostics`; healthy ≥ 85th pctile; **this is the metric that would have caught the skew on day one**

**Additional W39 fixes:**

M2 window (v0.6.0, Aug 6–Sep 11, n=110) is **retired, not failed.** The v0.6.x window was measuring a broken feature-serving pipeline. Every PF, WR, and PnL number from that window reflects a bot that was systematically selecting from the wrong part of its own model output — not from a flawed strategy.

Evidence:
- 111/111 exits via max_hold (barriers were dead code — 3.6× too wide)
- 111/111 entries were LONG (long-bias from the +0.00034 mean shift in corrupted predictions)

**M2 statistics should not be used as strategy evidence.** They are documented as an infrastructure failure case study.
